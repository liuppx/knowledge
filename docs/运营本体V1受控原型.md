# 运营本体 V1 受控身份原型

本原型是负责人批准的 Build small 第一个切片，验证对象身份、来源标识、权威 crosswalk、人工裁决和 Evidence provenance 的最小闭环。当前只在进程内存中运行，不连接生产 API 或数据库；进程结束后所有演练数据丢弃。

## 本地演示

演示只使用脚本内的虚构数据，不联网：

```bash
.venv/bin/python scripts/run_ontology_identity_prototype.py
```

领域服务位于 `knowledge/ontology/identity_prototype.py`。对象创建后默认为 `candidate`；评审者可标记 `ambiguous` 或 `insufficient_evidence`。只有来源标识已登记，并同时提供权威机构、规范化标识、Evidence 来源版本和证据 URI，才能将身份确认为 `confirmed`。每次评审会留下操作者、UTC 时间、理由及 Evidence 引用。

当一个外部标识被另一个对象认领时，系统不会覆盖已有归属或自动合并；`record_identifier_conflict` 会创建可审计的开放冲突记录，并将冲突双方都置为 `ambiguous`。裁决者可以用 `reject_identifier_claim` 驳回错误认领：记录裁决人、理由和 Evidence，保留标识原归属，并恢复冲突前状态。相同裁决重试幂等。当前原型不支持认定为同一实体后的对象合并或标识转移。

对象存在任一未结身份冲突时，状态保持为 `ambiguous`，不能通过其他 crosswalk 确认身份或手工改成其他状态。一个对象有多个开放冲突时，驳回其中一项不会提前解除歧义；全部冲突结案后才恢复冲突集打开前的状态。

原型内置一组最小角色边界，用于测试领域动作的授权关系：`contributor` 只能创建候选对象和登记来源标识；`reviewer` 可以创建/登记，并执行身份评审、权威 crosswalk 确认和冲突报告；`adjudicator` 只能执行冲突裁决。未注册的 actor 或越权角色会被拒绝。角色表是进程内测试策略，不负责认证 actor，也不替代 Wallet、Node 或生产服务的授权校验。

运行测试：

```bash
.venv/bin/pytest -q tests/test_ontology_identity_prototype.py
```

## 当前边界

- 仅用于公开或合成数据的开发演练；不持久化、不适用于多用户并发。
- 不做自动名称合并；同一来源命名空间中的标识不能分配给不同对象，冲突及其裁决状态会保留为审计记录。
- 身份确认要求明确的权威 crosswalk，名称相似或候选本身不够。
- 尚无认证、API、前端、数据库迁移、Release 集成或生产权限检查；原型角色策略只验证领域层的最小拒绝边界。
- Task 238 的独立评审、外部隐藏题集/真实 query log、授权工作流仍未完成；此原型不代表这些验证通过。
- 生产接入、增加对象范围或正式发布前，必须先完成相关验证和安全评审，并单独确认持久化及授权设计。
