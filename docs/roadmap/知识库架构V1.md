# 知识库架构 V1

> 状态：当前已实现能力清单与已知限制
>
> 更新日期：2026-11-10（版本基线 2026-08-03）

本文只回答两个问题：**哪些能力已经实现**，以及**当前有哪些已知限制**。系统如何组成、数据如何流动见[系统架构](../architecture/系统架构.md)，表和约束见[数据模型](../architecture/数据模型.md)，术语见[核心概念](../architecture/核心概念.md)，接口字段以 [OpenAPI](../openapi/knowledge.openapi.yaml) 为准。尚未实现的目标见[知识库架构 V2](知识库架构V2.md)。

判断规则：能力实现并有自动化测试后列入本文；本文未列出的能力，不应视为已经支持。

## 1. 已实现能力

### 1.1 身份与工作区

- 钱包签名登录、通行证登录（Passkey 与钱包身份出示）和 JWT 刷新/登出；开发环境 Demo 登录与示例知识库。
- 以钱包地址作为知识库所有者边界（owner-only）。
- 多知识库创建、编辑、删除、选择和最近使用恢复。

### 1.2 Warehouse 资产接入

- Knowledge App 目录边界；读凭证与读写凭证分离，密钥加密保存。
- Warehouse 浏览、预览、单文件或批量上传；文件或目录绑定源，绑定源关联读凭证。
- 上传记录和绑定状态查询。
- 文件读写经 `AssetStorePort`：导入、证据构建、运行产物、运行清单和表格分析均通过该端口访问 Warehouse。所有者绑定了未过期的 Warehouse Tool 凭证时走 HTTP Tool，否则走 S3/WebDAV 网关；Tool 无法读取的大对象回退到网关。详见 [Warehouse 集成收敛方案](../integrations/Warehouse集成收敛方案.md)。

### 1.3 来源接入与导入索引

- 来源类型 `warehouse`（默认）、`local_file`、`github_repository`；source scan 写入来源资产。
- 导入、重建、删除任务；基于绑定源创建任务；Worker 领取、心跳、取消、重试和失败状态；逐文件明细。
- Markdown、文本、PDF 等文件解析与切片；解析器、切片器可切换为 `ragflow` 适配，失败回退本地实现。
- 文档、切片和导入任务明细查询。

### 1.4 正式知识生产

- 证据单元构建与来源定位。
- 候选知识项生成、接受、拒绝；人工创建知识项。
- 知识项与修订版本模型；修订与证据关联。
- 知识项契约校验、review status 和 visibility status。

### 1.5 发布与授权

- 发布快照、当前发布版本解析。
- 热修（hotfix）和回滚（基于旧版本生成新版本）。
- 版本对比：`GET /kbs/{kb_id}/releases/{release_id}/diff?base=`，控制台发布页使用该接口。
- 服务主体和服务授权；授权可跟随当前版本或固定版本，可过期、可撤销。

### 1.6 检索

- `formal_only`、`evidence_only`、`formal_first` 三种检索模式，服务检索默认 `formal_first`。
- 混合检索：关键词召回与单元向量召回经 RRF 融合后重排；向量与重排仅在真实模型网关下生效，否则降级并在检索日志中记录。机制见[混合检索与真实模型落地设计](../architecture/混合检索与真实模型落地设计.md)。
- 向量存于数据库或 Weaviate；`POST /kbs/{kb_id}/reindex-units` 幂等回填单元向量。
- 检索日志审计；Search Lab 对比和来源健康度检查。

### 1.7 Agent 运行

- Agent Run 生命周期、产物元数据与来源信息、上下文引用、运行清单投影（投影失败可重试）；运行与检索日志关联。
- 表格分析运行（`spreadsheet_analysis`）：输入冻结、分阶段执行、CSV/XLSX profile、白名单分析计划（可由 Router 从自然语言生成）、结果 CSV/XLSX/PNG 与摘要，产物写回 Warehouse。
- 事件的 JSON 增量查询与 SSE（`Last-Event-ID` 续传）；取消；对失败或取消的运行重试（新建一次尝试，原运行不被改写）。
- 控制台 `/analysis-runs` 查看分析运行、事件流和下载产物。

接口和限制细节见 [CSV 与 Excel 分析 Agent 开发说明](../guides/CSV与Excel分析Agent开发说明.md)。

### 1.8 运营本体（实验性，默认关闭）

- 知识库下的本体对象、外部标识、身份评审、权威对照、标识冲突与裁决的持久化 API，owner-only；需设置 `ONTOLOGY_IDENTITY_ENABLED=true` 开启。范围与边界见[运营本体 V1 生产身份与证据切片](../ontology/运营本体V1生产身份切片.md)。

### 1.9 产品界面

- `web/` 下的 React SPA，FastAPI 只托管 `web/dist`。
- 工作区概览、资产仓库与 Tool 凭证管理、导入任务和来源文档、知识生产、检索验证、发布与授权、分析运行、运维状态和开发者接入。

### 1.10 工程与运行基线

- Alembic 迁移管理 schema；CI 在 PostgreSQL 上运行全量测试、迁移漂移检查、前端类型一致性检查、构建、镜像构建和 Weaviate 往返；离线检索评测作为非阻塞报告运行。
- 非 development 环境启动守卫：拒绝默认或占位的 JWT secret、`DEBUG=true`、`MODEL_PROVIDER_MODE=mock`、`WAREHOUSE_GATEWAY_MODE=mock` 和未显式设置的 token 加密密钥。

## 2. 已知限制

- **默认仍为替身配置**：`MODEL_PROVIDER_MODE=mock`、`VECTOR_STORE_MODE=db`；mock 下混合检索等价于纯关键词。尚无真实模型（live）评测或验收归档；现有产品验收报告在 mock 环境下得到。
- **治理**：没有发布审批流；没有自动化的知识冲突合并、事实过期判定和替代关系推理；知识地图按类型分类，没有显式知识关系边。
- **权限**：只有知识库所有者一种角色，没有协作者、审核者或组织级权限。
- **Warehouse**：目录同步依赖显式任务，不是事件驱动；缺少不可变版本标识，运行输入以路径 + ETag + sha256 作为过渡冻结键；尚无面向单次运行的委托凭证。
- **表格分析**：Worker 把输入整文件读入内存，尚无 DuckDB/PyArrow 流式处理和 Range 分段读取；没有自动重试（已支持手动重试）；取消运行中的运行时，Worker 不在阶段之间检查取消状态，会继续执行完剩余阶段；分析结果提升为知识（promote）尚未实现。
- **评测**：离线检索评测使用替身 provider，CI 中为非阻塞报告；答案层评分仍需人工。

以上限制的目标方案见[知识库架构 V2](知识库架构V2.md)。
