# 运营本体 V1 生产身份与证据切片

状态：Task #254 实现与验证中；数据库迁移尚未部署到生产环境。

本切片只将 Task 248 的受控身份原型扩展为持久化的身份与证据工作流，不代表通用本体平台已经建成，也不替代 Task 238 的独立产品验证。

## 范围

当前实现持久化 Knowledge Base 下的证据引用、领域对象、外部标识、身份评审、权威 crosswalk、标识冲突报告和冲突裁决。每项记录都绑定 `kb_id` 与 Knowledge Base owner；数据库复合外键进一步约束对象、证据、标识和评审只能互相引用同一知识库、同一 owner 的记录。

认证使用现有 Knowledge 钱包 access token。当前只有 Knowledge Base owner 可以执行本体读写；操作者由认证钱包注入，API 不接受请求体中的操作者字段。系统当前没有知识库协作者或独立 reviewer/adjudicator 角色。不能把 owner-only 能力描述成多人职责分离或本体专属 RBAC。

## 工作流约束

- 新对象以 `candidate` 创建，并追加初始评审和证据。
- 外部标识唯一约束为同一 KB 内 `(namespace, value)` 唯一；再次登记到同一对象是幂等请求，分配给其他对象则返回冲突，不覆盖归属。
- `confirmed` 只能由包含来源标识、规范化标识、authority 字段和证据引用的 crosswalk 创建；来源标识必须先登记到该对象。
- authority 当前由 Knowledge Base owner 在操作时提供并由其负责核验；本切片没有 authority 注册表或外部自动校验。
- 冲突报告保留报告证据并将双方置为 `ambiguous`；开放冲突阻止手工改身份状态或确认 crosswalk。
- 当前裁决只支持 `claim_rejected`，保留裁决证据和评审历史、恢复冲突前状态，不删除标识、不合并对象，也不自动转移标识。
- 相同标识登记、相同评审、crosswalk、冲突报告及裁决重试均按请求事实幂等；不同输入不能覆盖已有确认或裁决。

## API 与迁移

API 前缀为 `/kbs/{kb_id}/ontology`，均要求已有钱包认证：

| 操作 | 路径 |
| --- | --- |
| 新建/读取证据引用 | `POST /evidence`、`GET /evidence/{evidence_id}` |
| 新建/列出/读取对象 | `POST /objects`、`GET /objects`、`GET /objects/{object_id}` |
| 登记标识、评审、确认 crosswalk | `POST /objects/{object_id}/identifiers`、`/reviews`、`/crosswalks` |
| 报告并查询冲突 | `POST /objects/{claimant_object_id}/conflicts`、`GET /conflicts`、`GET /conflicts/{conflict_id}` |
| 裁决冲突 | `POST /conflicts/{conflict_id}/adjudications` |

Alembic revision `20261102_ontology_identity` 创建上述持久化表、唯一约束、检查约束、索引和 owner/KB 复合外键；downgrade 按依赖逆序删除本体表并移除 Knowledge Base 复合唯一约束。知识库删除流程也会按依赖顺序清理本体记录。

API 默认关闭。先按正式发布流程备份并执行 `alembic upgrade head`，完成授权和迁移验收后，才在受控环境设置 `ONTOLOGY_IDENTITY_ENABLED=true`（或对应 `[ontology]` TOML 项）开放路由。关闭开关会对该路由返回 404。仅通过测试数据库上的迁移演练不能作为生产迁移已执行的证据。

## 验证与边界

自动化覆盖 owner 隔离、操作者不可由请求伪造、重复请求、重复标识竞争、未决冲突拦截确认、证据/评审历史、拒绝认领与不合并对象。详细状态和 OpenAPI 以当前源码与生成契约为准。

Task 238 的隐藏题集、独立标注一致性、真实或授权脱敏工作流、维护成本等验证仍独立待完成。该切片交付本身不证明一般化运营本体有产品增益；在这些门槛有结论前，不扩展自动解析、对象合并、关系图、Agent Action 或面向所有用户的产品承诺。
