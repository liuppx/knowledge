# 部署指南

Knowledge 以**一个镜像、两种进程**交付：同一镜像既跑 API（含打包好的 Web 控制台），也跑导入 worker。数据面只依赖 PostgreSQL（真相源）；Weaviate 是可选的 ANN 加速层；Warehouse 对象存储与模型网关是外部依赖。

## 1. 镜像

`Dockerfile` 为多阶段构建：Node 24 构建 `web/dist` → Python 3.12 运行时安装 `requirements.txt`、拷贝 `knowledge/`、`migrations/`、`alembic.ini` 与前端产物，非 root 用户运行，内置 `/health` 健康检查。

```bash
docker build -t knowledge:$(git rev-parse --short HEAD) .
```

启动时 `knowledge.main` 的 lifespan 会执行 Alembic `upgrade head`，因此**不需要单独的迁移步骤**；多副本同时启动时 Alembic 以数据库锁串行化。

## 2. docker compose（单机 / 内测）

```bash
cp .env.template .env          # 填写 JWT_SECRET、TOKEN_ENCRYPTION_SECRET、模型网关等
docker compose up --build -d   # postgres + weaviate + api + worker
docker compose up -d --scale worker=3
docker compose logs -f api worker
```

- `api` 监听 `8000`，`/` 即 Web 控制台，`/docs` 为接口文档。
- compose 通过 `x-knowledge-env` 覆盖 `DATABASE_URL`、`WEAVIATE_*`、`WAREHOUSE_MOCK_ROOT`、`LOCAL_FILE_CONNECTOR_ROOT` 指向容器内地址；其余配置来自 `.env`（可选）。
- `worker` 的 `WORKER_NAME` 留空时由运行时按主机名生成，便于 `--scale`。
- 持久卷：`knowledge-postgres-data`（必须备份）、`knowledge-weaviate-data`（可重建）、`knowledge-app-data`（mock Warehouse / 本地来源，仅开发）。

## 3. 生产配置要点

`APP_ENV` 不为 `development` 时启动守卫生效（见 `knowledge/core/settings.py: validate_runtime_settings`），以下任一缺失会拒绝启动：

| 变量 | 要求 |
| --- | --- |
| `JWT_SECRET` | 长随机值，不能是模板占位 |
| `TOKEN_ENCRYPTION_SECRET` | 必须显式设置（加密 Warehouse 凭证） |
| `DEBUG` | `false` |
| `MODEL_PROVIDER_MODE` | `openai_compatible` + `MODEL_GATEWAY_BASE_URL`（Router） |
| `WAREHOUSE_GATEWAY_MODE` | 不能是 `mock`；生产走 `OBJECT_STORAGE_ENDPOINT` |

其他建议：

- `VECTOR_STORE_MODE=weaviate` 并按《向量索引运维手册》完成首次全量再索引；Weaviate 不可用时检索自动降级为关键词，不会 500。
- `EMBEDDING_DIMENSIONS` 必须与真实 embedding 模型一致（如 1536）；切模型 = 重建 Weaviate class + 全量再索引。
- 反向代理需透传 `Authorization` 与 `X-Service-Api-Key`，并对 `/analysis-runs/*/events/stream` 关闭缓冲（SSE）。
- 同一套 `.env` 供 API 与 worker 共用；worker 数量上限与租约见《Worker 部署与扩缩容建议》。

## 4. 不用容器

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
(cd web && npm ci && npm run build)          # 产物在 web/dist，FastAPI 直接服务
.venv/bin/uvicorn knowledge.main:app --host 0.0.0.0 --port 8000
./scripts/run_worker.sh 1                    # 需要几个起几个
```

## 5. 上线检查

1. `GET /health` 200；`/` 返回控制台；`/ops/stores/health`（登录后）显示数据库 / 向量库 / 模型网关 / 对象存储状态。
2. 用真实部署地址跑产品验收：`.venv/bin/python scripts/product_acceptance.py --base-url https://<host>`（mock Warehouse 不可用时请改用真实上传路径或 `--keep` 保留排查）。
3. 评测门禁：`KNOWLEDGE_EVAL_PROVIDER=live ./scripts/test.sh --suite eval`，归档报告。
4. 备份恢复演练一次，见《备份与恢复手册》。

## 6. CI

`.github/workflows/ci.yml` 的 `image` job 在每次 push / PR 构建镜像并做导入冒烟，保证 Dockerfile 与依赖始终可构建；发布镜像到仓库需按部署环境另行配置推送步骤。
