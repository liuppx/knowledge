# 部署指南

Knowledge 是一个独立产品，通过统一命令启动、停止和检查。底层进程划分属于实现细节，不要求使用者分别管理。数据面依赖 PostgreSQL；Weaviate 是可选的 ANN 加速层；对象存储与模型网关是外部依赖。默认使用命令行脚本和系统服务管理，不依赖 Docker。

## 1. 命令行启动（推荐）

本地开发直接运行后端和后台任务进程，它们属于同一个 Knowledge 产品：

```bash
# 终端一：后端开发服务
source .venv/bin/activate
python -m uvicorn knowledge.main:app --reload --host 127.0.0.1 --port 8002

# 终端二：后台任务处理
source .venv/bin/activate
python -m knowledge.workers.runner
```

只调试页面、接口或检索时可以暂时不运行第二个终端；导入、重建索引、删除等异步任务需要后台任务处理进程。

准备本机 Python、Node.js、PostgreSQL 和 `.env` 后：

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
(cd web && npm install && npm run build)
scripts/starter.sh start
scripts/starter.sh status
```

生产环境的整体启停、状态和日志：

```bash
scripts/starter.sh stop
scripts/starter.sh restart
tail -f logs/api.log logs/worker.log
```

### 配置

服务的配置由两层 TOML 文件驱动，存放在仓库 `config/`（随 `scripts/package.sh` 一起发布）：

- `config/defaults.toml` —— 全部字段的基线值，与代码默认值一致，一般不改。
- `config/local.toml` —— 部署主机的覆盖项。仓库里的版本把所有键注释掉并给出生产最小集；在主机上取消注释并填入真实值。

优先级从高到低：**进程环境变量 > `.env` > `config/local.toml` > `config/defaults.toml` > 代码默认值**。键名与环境变量同名（小写 / 大写），分表只为可读性。未知键或 TOML 语法错误会在启动时直接报错（指出文件名），不会静默回退。`KNOWLEDGE_CONFIG_DIR` 可把配置目录指到仓库之外，`KNOWLEDGE_ENV_FILE` 可改变 `.env` 路径。修改后**重启服务**生效。

生成离线归档：

```bash
scripts/package.sh
```

## 2. systemd

## 1. 镜像

启动时 `knowledge.main` 的 lifespan 会执行 Alembic `upgrade head`，因此**不需要单独的迁移步骤**；多副本同时启动时 Alembic 以数据库锁串行化。

## 3. 容器化部署（非默认路径）

仓库仍保留 `Dockerfile` 和 `compose.yaml` 供已有容器环境参考，但本项目的本地调试、部署文档和推荐流程不以 Docker/Compose 为前提。

命令行部署请使用上一节的 `scripts/starter.sh`；内部并发策略由 systemd 管理，不要求操作者分别启停内部进程。

- Knowledge 默认监听 `8002`，`/` 即 Web 控制台，`/docs` 为接口文档。
- PostgreSQL、Weaviate、Warehouse 和模型网关均作为外部服务配置，不由 Knowledge 启停脚本管理。

## 3. 生产配置要点

`APP_ENV` 不为 `development` 时启动守卫生效（见 `knowledge/core/settings.py: validate_runtime_settings`），以下任一缺失会拒绝启动：

| 变量 | 要求 |
| --- | --- |
| `JWT_SECRET` | 长随机值，不能是模板占位 |
| `TOKEN_ENCRYPTION_SECRET` | 必须显式设置（加密 Warehouse 凭证） |
| `DEBUG` | `false` |
| `MODEL_PROVIDER_MODE` | `openai_compatible` + `MODEL_GATEWAY_BASE_URL`（Router） |
| `OBJECT_STORAGE_ENDPOINT` | 生产对象存储标准协议 endpoint |

其他建议：

- `VECTOR_STORE_MODE=weaviate` 并按《向量索引运维手册》完成首次全量再索引；Weaviate 不可用时检索自动降级为关键词，不会 500。
- `EMBEDDING_DIMENSIONS` 必须与真实 embedding 模型一致（如 1536）；切模型 = 重建 Weaviate class + 全量再索引。
- 反向代理需透传 `Authorization` 与 `X-Service-Api-Key`，并对 `/analysis-runs/*/events/stream` 关闭缓冲（SSE）。
- 同一套配置供 Knowledge 内部进程共用；后台并发与租约见《Worker 部署与扩缩容建议》。

## 4. 不用容器

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
(cd web && npm ci && npm run build)          # 产物在 web/dist，FastAPI 直接服务
.venv/bin/uvicorn knowledge.main:app --host 0.0.0.0 --port 8002
./scripts/run_worker.sh 1                    # 需要几个起几个
```

## 5. 上线检查

1. `GET /health` 200；`/` 返回控制台；`/ops/stores/health`（登录后）显示数据库 / 向量库 / 模型网关 / 对象存储状态。
2. 用真实部署地址跑产品验收：`.venv/bin/python scripts/product_acceptance.py --base-url https://<host>`（mock Warehouse 不可用时请改用真实上传路径或 `--keep` 保留排查）。
3. 评测门禁：`KNOWLEDGE_EVAL_PROVIDER=live ./scripts/test.sh --suite eval`，归档报告。
4. 备份恢复演练一次，见《备份与恢复手册》。

## 6. CI

`.github/workflows/ci.yml` 的 `image` job 在每次 push / PR 构建镜像并做导入冒烟，保证 Dockerfile 与依赖始终可构建；发布镜像到仓库需按部署环境另行配置推送步骤。
