# Knowledge 控制台操作手册

本文档面向测试、运营与交付同学，说明如何通过 Web 控制台（`web/`，React SPA）完成知识库联调、验证与排查。控制台由 FastAPI 直接服务：构建后访问后端根路径 `/` 即可；开发时 `cd web && npm run dev`。

控制台按五个工作台组织，左侧导航对应 URL：

| 工作台 | 路径 | 做什么 |
| --- | --- | --- |
| 知识库 / 概览 | `/kbs`、`/kbs/{id}/overview` | 创建、编辑、删除知识库；查看统计、当前发布、绑定状态与最近任务 |
| 资产与导入 | `/kbs/{id}/assets` | 绑定 Warehouse 目录、来源与资产、文档与 chunk、导入/重建/删除任务 |
| 知识生产 | `/kbs/{id}/production` | 构建 Evidence、审核候选、维护正式知识项与修订 |
| 检索台 | `/kbs/{id}/search` | 三模式对比检索、命中 provenance、检索日志、来源健康 |
| 发布与授权 | `/kbs/{id}/release` | 发布 / 热修 / 回滚 / 版本对比；服务主体与授权 |
| Warehouse | `/warehouse` | 读写凭证、一键初始化、上传、目录浏览 |
| 分析运行 / 运维 | `/runs`、`/ops` | Agent 分析运行；队列、worker、依赖健康、失败任务 |

URL 就是知识库上下文：切换顶部的知识库选择器会停留在当前工作台；刷新或重新打开 `/` 会回到上次使用的知识库概览。

## 1. 登录与准备

1. 打开 `/`，使用钱包身份授权登录（右上角可切换为夜莺通行证登录）。
2. 进入 **Warehouse**：若还没有凭证，用「一键初始化凭证」以登录钱包签名 challenge，由 Knowledge 代为创建 uploads 读写凭证；或手工填入读 / 写凭证。
3. 顶部徽标显示「凭证就绪」后即可浏览目录与上传。

说明：浏览与绑定使用读凭证，上传使用写凭证，两者语义不同不要混用；一把读凭证只对应一类目录。

## 2. 创建知识库

1. 进入 **知识库**，输入名称与描述创建。
2. 创建后自动进入该知识库概览；「设置」可修改描述与检索配置（`chunk_size` / `chunk_overlap` / `retrieval_top_k` / `memory_top_k` / `embedding_model`）。
3. 修改 embedding 模型或维度后需要全量再索引，见《向量索引运维手册》。

## 3. 上传与绑定资产

1. 在 **Warehouse** 上传文件到 `uploads/` 目录（支持多文件，逐个显示结果），或直接在目录树中浏览已有目录。
2. 进入 **资产与导入 → 绑定**，点「绑定新路径」，在目录浏览器中选择目录或文件；绑定使用当前选择的读凭证。
3. 绑定可启用 / 禁用、解绑；每个绑定可单独「导入 / 重建 / 删除索引」，也可对全部启用绑定批量导入。

## 4. 导入与任务治理

1. **资产与导入 → 任务**：输入 Warehouse 路径可直接创建导入 / 重建索引 / 删除索引任务（删除需确认）；按绑定创建的任务也会出现在这里。
2. 有任务进行中时列表每 3 秒刷新；状态列显示排队位次与当前执行阶段。
3. 点击行打开任务详情：时间线、等待 / 执行耗时、worker、统计与逐文件明细（成功 / 跳过 / 失败及错误类型）。
4. 失败或部分成功的任务可「重试」；排队 / 执行中的任务可「取消」。
5. 没有常驻 worker 的环境可用「处理排队任务」手动跑一轮。
6. **文档** 页显示每个文件的处理状态与 chunk 数，打开详情可查看 chunk 文本与元数据；删除只移除索引，不动 Warehouse 原文件。

## 5. 知识生产：Evidence → 候选 → 正式知识项

1. **资产与导入 → 来源**：添加来源（Warehouse 目录 / 本地目录 / GitHub 仓库）并「扫描」得到资产清单。
2. **知识生产 → Evidence**：选择来源或资产，「构建 Evidence」；可按向量状态 / 类型筛选，点击行查看全文、来源定位与元数据。「回填向量索引」为混合检索补齐单元级向量。
3. 「生成候选」后进入 **候选审核**：接受（可先修订标题 / 陈述 / 类型）或拒绝；接受后自动跳到新知识项。
4. **知识项**：筛选、搜索、手工新建；详情展示当前修订、契约与来源信息、Evidence 关联（可跳转到对应 Evidence）与修订历史；「编辑」会生成新修订。

## 6. 发布、授权与检索验证

1. **发布与授权 → 发布版本**：「发布新版本」把已确认的知识项固化为可检索版本；任一版本可「热修」（选择知识项按当前修订合入）或「回滚到此」（基于旧版本生成新版本）；「对比…」查看两个版本的新增 / 移除 / 变更知识项。
2. **授权**：为消费方（Chat / Agent / Project）创建服务主体，API Key 只显示一次；再为本知识库新增授权（最新发布或固定版本、默认结果视图、到期时间），可暂停 / 恢复 / 吊销。
3. **检索台**：输入问题运行对比，三列分别是 Formal first / Formal only / Evidence only；每条命中可跳到知识项或 Evidence，并显示来源引用、资产可用性与排序依据。无命中时页面会给出下一步（导入 / 构建 Evidence / 发布）。
4. 检索日志记录控制台与 `/service/search*` 的每次查询，含混合检索 / rerank 的生效、跳过与降级原因；来源健康面板列出缺失 / 变更的资产。

## 7. 运维排查

进入 **运维**（需登录）：

- 排队 / 执行中 / 心跳过期任务数，平均等待与执行耗时
- PostgreSQL、向量库、模型网关、对象存储健康
- worker 列表（心跳、进行中、已处理、最近错误）
- 最近失败任务，可按 `trace_id` 过滤，点击编号直达任务详情

建议排查顺序：确认 release 与授权选择策略 → 检索日志看 query / mode / 信号 → 检索台对比三路结果 → 来源健康 → 失败任务与 worker。

## 8. 自动化验收

`scripts/product_acceptance.py` 会用《产品验证知识库》§2 的 11 篇文档走完上述整条链路并输出报告（见该文档 §7）。

## 9. 当前产品边界

- `knowledge` 不回写 chunk、embedding 或知识处理结果到 `warehouse`
- 配置写凭证和上传时，`knowledge` 可能在写凭证权限范围内创建当前 app 目录或目标上传目录
- 混合检索与 rerank 默认开启，但只在接入真实模型网关时生效；mock 环境下为纯关键词检索
- `memory` 保留为兼容模块，不在控制台导航中
- `warehouse` 是唯一资产中心
