# 运营本体 V1 合成演练包

> 状态：仅用于验证验证流程，不是生产数据，也不能作为用户需求证据。
>
> 演练日期基准：2026-10-24
>
> 上游门检：[运营本体 V1 构建风险评审](../../运营本体V1构建风险评审.md)

真实数据研究不得直接复用本目录的预期答案；正式方法和空模板见[运营本体 V1 实证研究方案](../../运营本体V1实证研究方案.md)和 [real-study](real-study/README.md)。没有内部数据时，可先执行[公开数据代理验证](../../运营本体V1公开数据代理验证.md)及其[运行说明](public-study/README.md)，但不得把代理结果解释为真实业务需求证据。

## 1. 目的

仓库和当前数据库没有可用的合同、产品、组织样本。本目录先用合成数据验证以下事情是否能被清楚表达和人工判定：

- 同一个业务对象在不同文件中使用不同名称，但通过稳定外部 ID 归并；
- 合同关系具有生效和失效时间；
- 新合同替代旧合同，但旧 Release 仍能看到历史事实；
- 正式事实与候选冲突事实同时存在，不能静默覆盖；
- Evidence 缺失后，事实应标记为 stale，而不是继续作为可靠结论；
- 结构化事实和现有文本检索可以用同一组问题做对照。

本演练不会新增数据库表、API、前端页面或图数据库。

## 2. 文件

| 文件 | 用途 |
| --- | --- |
| [objects.csv](objects.csv) | 合同、产品和组织对象，以及稳定外部标识和别名 |
| [assertions.csv](assertions.csv) | 带有效期、状态、Evidence 和 Release 边界的关系事实 |
| [questions.csv](questions.csv) | 10 个决策问题和 5 个文本检索控制问题 |
| [scorecard.csv](scorecard.csv) | 记录现有检索基线与人工事实表结果 |
| [evidence](evidence/) | 合成合同原文和来源状态说明 |

## 3. 场景摘要

合成场景包含：

- 5 份合同：`C-1001` 至 `C-1005`；
- 5 个产品：`P7` 至 `P11`；
- 3 个组织：`O1` 至 `O3`；
- `C-1002` 从 2026-06-01 起替代 `C-1001`；
- `C-1003` 与尚未批准的 `C-1004` 对产品 `P8` 在中国区形成冲突候选；
- `C-1005` 已于 2026-03-31 失效；
- `C-1003` 覆盖产品 `P10` 的附件来源被标记为缺失，因此相关断言为 stale；
- `O1` 在历史合同中使用旧名称，但外部 ID 始终为 `ORG-001`。

## 4. 演练步骤

### 4.1 文本检索基线

1. 将 `evidence/` 中除 `E-C1003-P10-missing.md` 外的 Markdown 文件作为普通来源导入一个独立测试知识库。
2. 使用当前 Evidence 或 formal-first 检索逐题运行 `questions.csv`。
3. 把回答、引用、耗时和结论填写到 `scorecard.csv` 的 `rag_*` 列。
4. 不向模型提供 `objects.csv` 和 `assertions.csv`，否则不再是文本检索基线。

### 4.2 人工事实表回答

1. 由知识运营人员使用 `objects.csv`、`assertions.csv` 和 Evidence 回答同一组问题。
2. 当前事实按 `as_of=2026-10-24` 判断。
3. `confirmed` 可以形成正式答案；`candidate` 必须作为待审核分歧展示；`stale` 只能作为风险提示，不能作为可靠结论。
4. 查询指定 Release 时，使用断言的 `release_from` 和 `release_to` 判断可见性。
5. 将结果填写到 `scorecard.csv` 的 `ontology_*` 列。

### 4.3 业务复核

由一名未参与事实表制作的使用者复核：

- 是否看得懂当前结论；
- 是否知道结论适用于什么时间和范围；
- 是否能定位到原文 Evidence；
- 是否能看到冲突、候选和 stale 状态；
- 是否会根据答案作出实际判断、审批或 Agent 动作。

## 5. 判定规则

决策题为 `Q01` 至 `Q10`。单题只有同时满足以下条件才算通过：

1. `answer_correct=yes`；
2. `evidence_traceable=yes`；
3. 时间范围、Release 或冲突状态没有被忽略；
4. 没有把 `candidate` 或 `stale` 事实表述为已确认事实。

演练通过不代表立即构建产品，只表示验证材料和评分方法可用于真实样本。进入真实 V1 构建仍必须满足：

- 真实或脱敏数据的决策题至少通过 8/10；
- 至少 3 题明确依赖关系或时态过滤；
- 至少 1 题影响真实判断、审批、检索范围或 Agent 动作；
- 运营人员而非开发者能够维护事实和解释冲突。

## 7. 替换为真实样本

真实验证时复制本目录结构，但必须替换所有对象、断言和 Evidence。建议保留字段和问题类型，便于比较；不要把合成对象混入真实 KnowledgeBase。

真实材料进入仓库前必须：

- 完成脱敏和访问授权；
- 明确合同、产品和组织的权威外部标识；
- 明确谁可以审核事实；
- 明确 Evidence 文件是否允许被 Chat、Agent 或 Project 消费；
- 不提交真实客户、员工、商业金额、密钥或个人信息。
