# 混合检索向量索引运维手册（Weaviate + Postgres）

面向部署/运维：单元级向量索引（evidence/formal）的上线、再索引、切模型维度与故障处理。检索读路径永不因向量后端抖动而失败——任何异常都降级为 lexical-only（见《混合检索与真实模型落地设计》§6）。

## 1. 架构约定：谁是真相源

- **Postgres `unit_embeddings` 表是向量的唯一真相源**（可迁移、可备份、随 schema 演进）。
- **Weaviate 是从 Postgres 重建的 ANN 加速层**，可随时清空重建，不承载不可恢复数据。
- 后端由 `VECTOR_STORE_MODE` 选择：`db`（默认，逐 KB 余弦，无外部依赖）或 `weaviate`（ANN）。`weaviate` 不可达时读路径自动降级。

## 2. 首次上线 Weaviate

1. 起服务：`docker compose up -d weaviate`（`compose.yaml` 已含 `weaviate` 服务与健康检查）。
2. 配置环境：
   ```
   VECTOR_STORE_MODE=weaviate
   WEAVIATE_HOST=<host>            WEAVIATE_PORT=8080     WEAVIATE_GRPC_PORT=50051
   WEAVIATE_SCHEME=http|https      WEAVIATE_API_KEY=<可选>
   WEAVIATE_UNIT_INDEX_NAME=KnowledgeUnit   # 与 chunk 的 KnowledgeChunk 分离
   ```
3. 健康检查：`GET /ops/stores/health` 返回 `vector_store_status.ready == true`。
4. 全量再索引每个 KB（幂等）：`POST /kbs/{kb_id}/reindex-units`（KB owner 鉴权）。
   - 响应含 `indexed`/`skipped` 与 `weaviate.{status,indexed}`。`weaviate.status != "ok"` 表示镜像写失败——**Postgres 已写成功**，读路径仍可用（降级或 DB 后端），修复 Weaviate 后重跑即可。

## 3. 再索引（reindex）语义

- `reindex-units` 只重嵌 **text 变化** 的单元（按 `text_hash`），未变的跳过——常态运维可安全重复调用。
- 触发时机：新建/更新 evidence 后；切换 embedding 模型后（见 §4）；Weaviate 数据丢失后重建。
- 未再索引的 KB：`_search_evidence` 查不到已索引向量 → `vector_signal="active_no_index"` → 自动 lexical-only，不返回坏结果。

## 4. 切换 embedding 模型 / 维度（高危）

`unit_embeddings` 与 Weaviate class 的向量**按 `embedding_model` 分区**，不同模型互不干扰；但**同一 class 内不可混维**。切模型/维度顺序：

1. 更新 `EMBEDDING_MODEL`（及必要的 `EMBEDDING_DIMENSIONS` / 网关配置）。
2. **重建 Weaviate class**：删除旧 `KnowledgeUnit` class（或换 `WEAVIATE_UNIT_INDEX_NAME` 到新名）——因为 Weaviate class 的向量维度固定，换维必须重建，不能就地追加。
3. 对所有 KB 重跑 `POST /kbs/{kb_id}/reindex-units`：新 `embedding_model` 分区从零建立。
4. 旧模型的 `unit_embeddings` 行可保留（查询按当前 `embedding_model` 过滤，自动忽略旧维度行）或按需清理。

> 遗漏第 2 步会静默返回坏结果（新查询向量对旧维度库）——切维必须走完整重建。

## 5. 故障处理

| 现象 | 处置 |
|---|---|
| `/ops/stores/health` vector 非 ready | 检查 Weaviate 容器/网络；读路径此时已降级 lexical-only，不阻塞线上 |
| `reindex` 返回 `weaviate.status: error` | Postgres 已写；修复 Weaviate 后重跑 reindex |
| 检索质量异常疑似坏索引 | 临时 `VECTOR_STORE_MODE=db` 回退到 Postgres 余弦；排查后再切回 |
| Weaviate 数据丢失 | 无需恢复备份，直接对各 KB 重跑 reindex 从 Postgres 重建 |

## 6. CI 覆盖

`.github/workflows/ci.yml` 的 `weaviate-roundtrip` job 起 Postgres+Weaviate，跑 `tests/test_weaviate_unit_index.py` 验证 upsert / near_vector / kb 过滤 / 幂等的真实往返；本地 `--suite all` 无 Weaviate 时该用例自动 skip。
