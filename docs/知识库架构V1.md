# 知识库架构 V1

> 状态：当前已实现架构
>
> 版本基线：2026-08-03（2026-11-07 补充：混合检索、表格分析 Run、知识源端口化、Release 回滚、工程基线）

## 1. 定位

Knowledge V1 是面向人和 Agent 的版本化知识控制面，负责把 Warehouse 中的原始资产加工为可追溯、可审核、可发布和可检索的正式知识。

根据[社区产品关系与开发边界](社区产品关系与开发边界.md)：

- Knowledge 拥有知识生产流程、Evidence、Knowledge Item、Release、Grant、RetrievalLog、AgentRun 和 artifact provenance。
- Warehouse 拥有文件内容、目录、对象版本、checksum、存储权限和凭证。
- Wallet 提供用户身份、签名和授权确认。
- Router 提供模型路由、额度和计量。
- Chat、Project 和 Agent 是知识与运行能力的消费方，不应复制 Knowledge 的知识模型。

Knowledge 不实现文件系统权限，不持有用户钱包私钥，也不替代 Agent 管理长期运行的智能体进程。

## 2. V1 已实现能力

### 2.1 身份与工作区

- 钱包 challenge、签名验证和 JWT 登录。
- 开发环境 Demo 登录与示例知识库。
- 钱包地址作为当前知识库所有者边界。
- 多知识库创建、编辑、删除、选择和最近使用恢复。

### 2.2 Warehouse 资产接入

- Knowledge App 目录边界。
- 读凭证和写凭证分离。
- Warehouse 浏览、预览、单文件或批量上传。
- 文件或目录绑定源。
- 绑定源与读凭证关联。
- 上传记录和绑定状态查询。
- 知识源端口化：`SourceConnectorPort`、`DocumentParserPort`、`DocumentChunkerPort`；source connector 支持 `warehouse`（默认）、`local_file`、`github_repository`，经 source scan 写入 `SourceAsset` 并进入 Evidence 构建。
- parser/chunker 默认 `local`，可显式启用 `ragflow` 适配（`knowledge/adapters/ragflow`），失败回退本地实现；第三方源码快照位于 `knowledge/third_party`。

### 2.3 导入与索引

- import、reindex 和 delete 任务。
- 基于绑定源创建任务。
- Worker claim、heartbeat、取消、重试和失败状态。
- Markdown、文本、PDF 等文件解析。
- chunk 切分、embedding 记录和向量检索。
- 文档、chunk 和导入任务明细查询。

### 2.4 正式知识生产

- Source 与 SourceAsset 资产清单。
- EvidenceUnit 构建和来源定位。
- KnowledgeItemCandidate 候选知识项。
- 候选接受、拒绝和人工创建知识项。
- KnowledgeItem 与 KnowledgeItemRevision 版本模型。
- KnowledgeItemEvidenceLink 证据关联。
- item contract 校验、review status 和 visibility status。

### 2.5 发布与服务检索

- KBRelease 和 KBReleaseItem 发布快照。
- 当前发布版本解析。
- ServicePrincipal 和 ServiceGrant 服务授权。
- pinned release 与 current release 选择。
- formal、evidence 和 formal-first 三种检索模式。
- 混合检索：权限/可用性过滤前置后，关键词召回（ASCII 词 + CJK 二元组）与单元级向量召回（`UnitEmbeddingRecord`，DB 或 Weaviate 后端）经 RRF 融合，再对前 `rerank_top_m` 名做 rerank。向量与 rerank 只在真实模型网关（`model_provider_mode=openai_compatible`）下激活；mock、未回填或调用失败时降级为关键词/RRF 顺序，并在 RetrievalLog trace 中记录。
- `POST /kbs/{kb_id}/reindex-units` 幂等回填单元级向量。
- Release 热修（hotfix）和回滚（基于旧版本生成新版本），API 与控制台界面均可用。
- Release 版本对比：`GET /kbs/{kb_id}/releases/{release_id}/diff?base=` 按已存快照将知识项分为新增/移除/变更/未变，控制台发布页对比抽屉使用该接口。
- RetrievalLog 检索审计。
- Search Lab 对比和来源健康度检查。

### 2.6 Agent Run

- AgentRun 生命周期记录。
- AgentRunArtifact 元数据和 provenance。
- Context Reference 与 manifest 生成。
- Agent Run 与 RetrievalLog 关联。
- Warehouse manifest 投影，manifest 同步失败可重试。
- `spreadsheet_analysis` Run：`queued -> running -> completed/failed/cancelled`，`AgentRunInput` 冻结输入，`AgentRunStep` 记录阶段，`AgentRunEvent` 记录递增事件；常驻 Worker 执行 CSV/XLSX profile、白名单分析计划（可由 Router 从自然语言生成）、结果 CSV/XLSX/PNG 和 summary，产物登记为 Artifact 并写回 Warehouse。
- 事件接口支持 JSON 增量查询和 SSE（`Last-Event-ID` 续传）；`POST /service/runs/{run_id}/cancel` 取消 Run；`POST /service/runs/{run_id}/retry` 对 failed/cancelled 的 Run 基于冻结输入新建一次尝试（`attempt`、`retry_of_run_id`），原 Run 不被改写。控制台通过 `/analysis-runs` 查看分析运行、事件流和下载产物。细节与限制见[CSV 与 Excel 分析 Agent 开发说明](CSV与Excel分析Agent开发说明.md)。

### 2.7 产品界面

- 独立钱包登录和 Demo 入口。
- 无知识库、已选择知识库和切换中状态。
- 工作区概览、资产仓库、导入任务和来源文档。
- 知识项列表、分类地图和详情抽屉。
- 检索验证、运维状态和开发者接入。
- 前端为 `web/` 下的 React SPA，FastAPI 只服务 `web/dist`。

### 2.8 工程与运行基线

- 数据库 schema 由 Alembic 迁移管理（`migrations/versions/`）。
- CI（`.github/workflows/ci.yml`）在 PostgreSQL 上运行全量 pytest，并构建 web、验证 Weaviate 往返；离线检索评测（Q01–Q12）作为非阻塞报告运行。
- 非 development 环境启动守卫：拒绝默认/占位 JWT secret、`DEBUG=true`、`model_provider_mode=mock`、`warehouse_gateway_mode=mock` 和未显式设置的 token 加密密钥。

## 3. V1 核心模型

```text
KnowledgeBase
  ├── SourceBinding ── WarehouseCredential
  ├── ImportedDocument ── ImportedChunk ── EmbeddingRecord
  ├── Source ── SourceAsset ── EvidenceUnit
  ├── KnowledgeItemCandidate
  ├── KnowledgeItem ── KnowledgeItemRevision ── KnowledgeItemEvidenceLink
  ├── KBRelease ── KBReleaseItem
  ├── ServiceGrant ── ServicePrincipal
  ├── UnitEmbeddingRecord
  ├── RetrievalLog
  └── AgentRun ── AgentRunInput / AgentRunStep / AgentRunEvent / AgentRunArtifact
```

## 4. V1 写路径

```text
Wallet 登录
  -> 创建 KnowledgeBase
  -> 导入 Warehouse 凭证
  -> 上传或绑定资产
  -> 创建 ImportTask
  -> Worker 解析与切片
  -> ImportedDocument / ImportedChunk / EmbeddingRecord
  -> Source / SourceAsset / EvidenceUnit
  -> Candidate / KnowledgeItem / Revision
  -> KBRelease
```

## 5. V1 读路径

```text
用户或服务请求
  -> JWT 或 ServicePrincipal 鉴权
  -> 选择 workspace/current/pinned release
  -> formal / evidence / formal-first 检索（关键词 + 向量 RRF 融合 + rerank，按条件降级）
  -> 返回知识、证据和来源引用
  -> 写入 RetrievalLog
```

## 7. V1 已知限制

- 默认配置为 `model_provider_mode=mock`、`vector_store_mode=db`；mock 下混合检索与 rerank 不激活，等价纯关键词。生产模型质量取决于部署配置，尚无真实模型（live）评测或验收归档。
- 知识地图目前按类型分类，不包含显式知识关系边。
- 没有自动化的知识冲突合并、事实过期判定和替代关系推理。
- 没有发布审批流。
- Warehouse 目录同步主要依赖显式任务，不是完整事件驱动同步。
- 离线检索评测执行器和产品验收脚本（`scripts/product_acceptance.py`）已建立，但离线评测使用替身 provider，CI 中为非阻塞报告；答案层评分仍需人工。
- 表格分析 Worker 读取完整对象，尚无 DuckDB/PyArrow 流式处理、Range 分段读取和自动重试（已支持手动 retry）；Worker 不在阶段之间检查取消状态。

这些限制属于 V2 范围，不应在 V1 文档中描述为已经支持。
