# 知识库架构 V1

> 状态：当前已实现架构
>
> 版本基线：2026-08-03

## 1. 定位

Knowledge V1 是面向人和 Agent 的版本化知识控制面，负责把 Warehouse 中的原始资产加工为可追溯、可审核、可发布和可检索的正式知识。

根据[社区产品关系与开发边界](社区产品关系与开发边界.md)：

- Knowledge 拥有知识生产流程、Evidence、Knowledge Item、Release、Grant、RetrievalLog、AgentRun 和 artifact provenance。
- Warehouse 拥有文件内容、目录、对象版本、checksum、存储权限和凭证。
- Wallet 提供用户身份、签名和授权确认。
- Router 提供模型路由、额度和计量。
- Chat、Project 和 Agent 是知识与运行能力的消费方，不应复制 Knowledge 的知识模型。

Knowledge 不实现文件系统权限，不持有用户钱包私钥，也不替代 Agent 管理长期运行的智能体进程。

## 2. V1 已实现能力

### 2.1 身份与工作区

- 钱包 challenge、签名验证和 JWT 登录。
- 开发环境 Demo 登录与示例知识库。
- 钱包地址作为当前知识库所有者边界。
- 多知识库创建、编辑、删除、选择和最近使用恢复。

### 2.2 Warehouse 资产接入

- Knowledge App 目录边界。
- 读凭证和写凭证分离。
- Warehouse 浏览、预览、单文件或批量上传。
- 文件或目录绑定源。
- 绑定源与读凭证关联。
- 上传记录和绑定状态查询。

### 2.3 导入与索引

- import、reindex 和 delete 任务。
- 基于绑定源创建任务。
- Worker claim、heartbeat、取消、重试和失败状态。
- Markdown、文本、PDF 等文件解析。
- chunk 切分、embedding 记录和向量检索。
- 文档、chunk 和导入任务明细查询。

### 2.4 正式知识生产

- Source 与 SourceAsset 资产清单。
- EvidenceUnit 构建和来源定位。
- KnowledgeItemCandidate 候选知识项。
- 候选接受、拒绝和人工创建知识项。
- KnowledgeItem 与 KnowledgeItemRevision 版本模型。
- KnowledgeItemEvidenceLink 证据关联。
- item contract 校验、review status 和 visibility status。

### 2.5 发布与服务检索

- KBRelease 和 KBReleaseItem 发布快照。
- 当前发布版本解析。
- ServicePrincipal 和 ServiceGrant 服务授权。
- pinned release 与 current release 选择。
- formal、evidence 和 formal-first 三种检索模式。
- RetrievalLog 检索审计。
- Search Lab 对比和来源健康度检查。

### 2.6 Agent Run

- AgentRun 生命周期记录。
- AgentRunArtifact 元数据和 provenance。
- Context Reference 与 manifest 生成。
- Agent Run 与 RetrievalLog 关联。
- Warehouse manifest 投影。

### 2.7 产品界面

- 独立钱包登录和 Demo 入口。
- 无知识库、已选择知识库和切换中状态。
- 工作区概览、资产仓库、导入任务和来源文档。
- 知识项列表、分类地图和详情抽屉。
- 检索验证、运维状态和开发者接入。

## 3. V1 核心模型

```text
KnowledgeBase
  ├── SourceBinding ── WarehouseCredential
  ├── ImportedDocument ── ImportedChunk ── EmbeddingRecord
  ├── Source ── SourceAsset ── EvidenceUnit
  ├── KnowledgeItemCandidate
  ├── KnowledgeItem ── KnowledgeItemRevision ── KnowledgeItemEvidenceLink
  ├── KBRelease ── KBReleaseItem
  ├── ServiceGrant ── ServicePrincipal
  ├── RetrievalLog
  └── AgentRun ── AgentRunArtifact
```

## 4. V1 写路径

```text
Wallet 登录
  -> 创建 KnowledgeBase
  -> 导入 Warehouse 凭证
  -> 上传或绑定资产
  -> 创建 ImportTask
  -> Worker 解析与切片
  -> ImportedDocument / ImportedChunk / EmbeddingRecord
  -> Source / SourceAsset / EvidenceUnit
  -> Candidate / KnowledgeItem / Revision
  -> KBRelease
```

## 5. V1 读路径

```text
用户或服务请求
  -> JWT 或 ServicePrincipal 鉴权
  -> 选择 workspace/current/pinned release
  -> formal / evidence / formal-first 检索
  -> 返回知识、证据和来源引用
  -> 写入 RetrievalLog
```

## 7. V1 已知限制

- 默认模型和向量服务可运行在 mock 或本地模式，生产模型质量取决于部署配置。
- 知识地图目前按类型分类，不包含显式知识关系边。
- 没有自动化的知识冲突合并、事实过期判定和替代关系推理。
- 没有完整的发布 diff、审批流和一键回滚产品界面。
- Warehouse 目录同步主要依赖显式任务，不是完整事件驱动同步。
- 验证问题和评分标准已经建立，但还没有自动评测执行器。

这些限制属于 V2 范围，不应在 V1 文档中描述为已经支持。
