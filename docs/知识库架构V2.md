# 知识库架构 V2

> 状态：目标架构，尚未完整实现
>
> 前置基线：[知识库架构 V1](知识库架构V1.md)

## 1. V2 目标

V2 在 V1 的可追溯知识生产与发布模型上，增加持续同步、智能治理、显式知识关系、自动评测和更稳定的跨系统交付能力。

本文只记录尚未完成的目标，不作为当前接口或产品能力承诺。实现状态应以代码、OpenAPI 和 V1 文档为准。

## 2. 持续知识同步

目标能力：

- Warehouse 资产变更事件驱动增量同步。
- 按 source、目录或资产配置同步策略和频率。
- 文件新增、修改、移动和删除的统一语义。
- 失败断点续跑和大规模目录增量扫描。
- source freshness SLA 和同步延迟指标。

V1 已有显式 import/reindex/delete 任务，但尚未形成完整事件驱动闭环。

## 3. LLM 知识整理

目标能力：

- 使用模型生成候选事实、规则、流程、FAQ 和决策记录。
- 多 Evidence 聚合为单个 Knowledge Item。
- 自动识别重复、冲突、过期和替代关系。
- 支持人工审核、批量接受和审核策略。
- 记录模型、prompt、token、输入 Evidence 和生成参数。

V1 已有 Candidate、Item、Revision 和 Evidence Link，但候选生成仍以确定性流程为主，没有完整的持续 LLM 治理系统。

## 4. 知识关系图

目标能力：

- KnowledgeItemRelation 显式关系模型。
- 支持 depends_on、supersedes、conflicts_with、derived_from、applies_to 等关系。
- 图谱浏览、关系筛选和影响分析。
- 发布时冻结关系快照。
- 检索时使用关系扩展和路径解释。

V1 的“知识地图”是分类浏览，不代表已经实现知识图谱。

## 5. 版本治理与发布

目标能力：

- Release diff、影响范围和来源变化说明。
- 审批人、审批策略和发布门禁。
- 灰度发布、环境 promotion 和一键回滚。
- 按服务或 Agent 固定版本并显示升级建议。
- 对失效 Evidence 和 stale source 自动生成修订任务。

V1 已有 release snapshot、pinned grant 和 current release，但缺少完整治理界面和自动策略。

## 6. 自动评测

目标能力：

- 将[产品验证知识库](产品验证知识库.md)中的问题集结构化保存。
- 自动运行检索与答案生成。
- 对正确性、引用、覆盖率和拒答进行评分。
- 对不同 chunk、embedding、rerank 和模型配置做对比实验。
- 发布前执行质量门禁并保留历史趋势。

## 7. 多租户与组织治理

目标能力：

- 从钱包所有者扩展到组织、团队和成员角色。
- 知识库级 owner、editor、reviewer、reader 权限。
- 服务身份最小权限和授权审批。
- 审计日志导出、保留策略和合规删除。
- 跨知识库引用但不复制源内容。

## 8. 跨系统交付

目标能力遵循[社区产品关系与开发边界](社区产品关系与开发边界.md)：

- Chat 使用 Knowledge 创建 Agent Run、检索知识并记录 artifact provenance。
- Project 通过 Agent 或受控服务接口消费正式发布知识。
- Agent 使用 Node release 和 Router 模型能力，不把运行时状态写入 Knowledge。
- Warehouse 保持文件内容和权限的唯一数据面。
- OpenAPI、事件 schema 和 artifact manifest 统一版本化。

## 9. V2 建议实施顺序

1. 自动评测执行器和发布质量门禁。
2. Warehouse 增量同步与 freshness 指标。
3. LLM Candidate 生成、冲突检测和审核工作台。
4. KnowledgeItemRelation 与关系图。
5. Release diff、审批和回滚。
6. 组织权限与跨知识库治理。

每一项进入 V1 前，必须同时满足：

- 数据模型与迁移已经落地。
- OpenAPI 契约已经发布。
- 控制台或服务调用闭环可验证。
- 测试覆盖关键权限和失败语义。
- 文档从“目标”改写为“当前事实”。
