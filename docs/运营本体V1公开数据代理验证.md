# 运营本体 V1 公开数据代理验证

> 状态：公开代理数据可用性与完整性验证已执行；尚未执行 Knowledge 检索效果实验。
>
> 执行日期：2026-10-25。
>
> 对应研究协议：[运营本体 V1 实证研究方案](运营本体V1实证研究方案.md)。

## 1. 结论

可以使用公开数据继续验证，而且不需要先虚构企业内部数据。公开来源已经足以构造一套可复现的技术代理研究，用来检验：

- 合同结论是否能回到原始 Evidence span；
- `Entailment / Contradiction / NotMentioned` 是否被明确区分；
- 合同/采购对象是否具有稳定外部 ID；
- 修改、有效期和历史版本是否需要一等时态模型；
- 合同、产品/服务品类、买方和供应商是否可以形成可核验关系；
- 法人当前名称、历史名称和登记机关 ID 是否能够支持对象身份解析。

但公开数据不能替代全部真实验证。它不能证明 Knowledge 已有真实付费需求，不能测出你的组织维护本体的实际成本，也不能验证生产环境中的 Grant 泄漏风险。因此当前结论是：

> **Validate again：公开代理数据已经足够启动 A-F 实验，但不足以把结论升级为 Build small。**

## 2. 为什么选这五个来源

本次没有追求更多数据集，而是选择能够组成证据链的最小来源组合：

```text
原始合同 + 独立人工标注
  ContractNLI / CUAD
        ↓
合同—产品品类—组织—修改交易
  USAspending / TED
        ↓
组织稳定身份、历史名称、登记机关 crosswalk
  GLEIF
```

| 来源 | 最原始素材 | 独立金标或客观约束 | 主要验证对象 | 不能证明什么 |
| --- | --- | --- | --- | --- |
| ContractNLI | 607 份 NDA 原文，含 SEC 文件和公开 PDF | 17 个固定命题、三分类结论、人工 Evidence span | Evidence、否定、未知、冲突语义 | 多合同替代、产品主数据、业务价值 |
| CUAD | 510 份商业合同全文 | 律师监督下的 41 类条款与原文 offset | 当事方、签署/生效/到期/续期、条款 Evidence | 跨系统实体合并、权限 |
| USAspending | 美国政府 Award 与 transaction 原始公开记录 | Award ID、PIID、UEI、修改号、金额守恒、PSC/NAICS | 合同—组织—品类、修改时间线、金额重放 | 签署合同全文、内部审批 |
| TED | 欧盟官方采购通知和修改通知 | notice ID、previous notice、组织 ID、CPV、发布日期 | 通知版本链、多供应商、品类和组织关系 | 私有合同条款、企业内部授权 |
| GLEIF | 全球 LEI 参考记录 | LEI、登记机关 ID、当前/历史法定名称 | 对象身份、别名、更名、crosswalk | 所有非 LEI 组织的完整身份金标 |

选择原则是“一手记录 + 外部可核验约束”。ContractNLI/CUAD 的标签不是原始业务记录，但它们与原文同时提供，可作为独立于本项目的人工金标；USAspending、TED 和 GLEIF 则是官方记录本身。

## 3. 已执行的客观检查

检查由 [validate_public_ontology_data.py](../scripts/validate_public_ontology_data.py) 执行。两个静态数据集固定到 Git commit 和 SHA-256；三个 API 使用固定对象 ID。脚本只依赖 Python 标准库，输出 JSON，任何检查失败都会返回非零退出码。本次执行共运行 25 项断言，25 项通过、0 项失败，机器判定为 `proxy_data_ready`。

### 3.1 ContractNLI：Evidence 与未知状态

固定版本：

- Git commit：`eced6528dd3c1d14d73f9a87df8f7bdbc03126f9`；
- ZIP SHA-256：`e03fc77bbf8b53e2976a250e81d8a294bc3d5e5fb014521e477dee9340d6287b`；
- 许可：CC BY 4.0。

实测结果：

| 指标 | 结果 |
| --- | ---: |
| 合同文档 | 607 |
| 固定命题 | 17 |
| 文档—命题标注 | 10,319 |
| Entailment | 5,017 |
| Contradiction | 1,156 |
| NotMentioned | 4,146 |
| 非中性结论 | 6,173 |
| Evidence span 引用 | 11,973 |
| SEC 来源文档 | 232 |
| Evidence 越界、缺失或中性误带 Evidence | 0 |

这证明外部金标能够客观区分“支持”“反驳”“未提及”，且每个正式非中性结论都可以回放到原文 span。它适合测试 H2 和 H5 的技术部分，但不证明 Knowledge 已达到这些指标。

### 3.2 CUAD：合同身份与时态字段

固定版本：

- Git commit：`67faa0e6023b04fcaae6cc09497ab00e5d63a2a2`；
- ZIP SHA-256：`f8161d18bea4e9c05e78fa6dda61c19c846fb8087ea969c172753bc2f45b999a`；
- 许可：CC BY 4.0。

实测结果：

| 指标 | 结果 |
| --- | ---: |
| 商业合同 | 510 |
| 条款类别 | 41 |
| 问题实例 | 20,910 |
| 有答案问题 | 6,702 |
| 无答案问题 | 14,208 |

41 类中明确包含 `Document Name`、`Parties`、`Agreement Date`、`Effective Date`、`Expiration Date` 和 `Renewal Term`。这组数据能测试从合同原文抽取 `Contract / Organization / valid_from / valid_to / renewal qualifier / Evidence`，并保留大量无答案负样本。

### 3.3 USAspending：修改链和金额守恒

固定 Award：`CONT_AWD_ZN31_9700_W91QUZ06D0004_9700`。

官方记录给出：

- 收款组织：`HPI FEDERAL LLC`；
- 稳定外部标识：UEI `DJRUN4KK1HK3`；
- 采购方：美国国防部；
- PSC：`7021`，信息技术中央处理单元；
- NAICS：`334119`；
- 当前 Award obligation：`463050.00`。

同一 Award 有三条 transaction：

| 修改号 | 日期 | 动作 | obligation |
| --- | --- | --- | ---: |
| 0 | 2017-03-31 | 初始订单 | 463,059.00 |
| 1 | 2017-05-01 | 修改 CAGE，并延长交付日期 | 0.00 |
| 2 | 2025-05-15 | Close out | -9.00 |

客观重算：`463059 + 0 - 9 = 463050`，与 Award 当前总额完全一致；最新 transaction 日期也与 Award 的 `last_modified_date` 一致。这条样本直接证明“当前值”不能只保存为无历史的属性，修改交易和 valid/transaction time 必须可追溯。

### 3.4 TED：前后通知和组织—品类关系

固定修改通知：

- 当前 notice ID：`0d4b759d-089c-4b8b-97f0-91276cb03ce6`；
- publication number：`639634-2025`；
- 前一 notice ID：`ba7a1185-4e7d-4c71-a1bb-6f2099127aa5`；
- 前一 publication number：`47668-2025`。

检查结果：

- 当前通知的 `modification-previous-notice-identifier` 能解析到前一通知；
- 前一通知发表于 2025-01-23，修改通知发表于 2025-10-01，时间顺序成立；
- 买方标识 `40003857687` 在两个通知中保持稳定；
- 程序标题保持一致；
- CPV `45231400` 在两个通知中重合；
- 前一通知含多个 winner identifier，证明单一采购程序可能连接多个供应商对象。

这比只使用整理后的“合同摘要”更接近原始运营事实：对象关系、版本和品类都来自欧盟官方通知字段，且前后记录能够独立查询。

### 3.5 GLEIF：名称不是对象身份

固定 LEI：`WHKXQACZ14C5XRO8LW03`。

官方记录给出：

- 当前法定名称：`HP INC.`；
- 历史法定名称：`Hewlett-Packard Company`；
- 登记机关：`RA000602`；
- 登记机关实体 ID：`2858384`。

因此字符串名称不应成为 `DomainObject` 主键。对象身份至少需要 `LEI / registry authority / registry entity ID / source crosswalk`，历史名称只能作为带来源的 identifier 或 qualifier。

## 4. 对研究假设的影响

| 假设 | 公开数据目前能证明 | 仍未证明 |
| --- | --- | --- |
| H1 决策正确性 | 已有足够原文、关系和隐藏金标可执行 A-F 比较 | Knowledge 是否比当前混合检索提高 10 个百分点 |
| H2 Evidence 完整性 | 外部金标 Evidence locator 完整，offset 零错误 | Knowledge 正式答案是否达到 100% 可追溯 |
| H3 时态与 Release | USAspending/TED 存在真实修改链，可构造 as-of 问题 | Knowledge 的时间正确率和 Release 重放率 |
| H4 对象身份 | GLEIF 提供稳定 ID、历史名称和 registry crosswalk | 在目标样本上的 precision、recall、false merge |
| H5 冲突和失效 | ContractNLI 提供 contradiction/not-mentioned 金标；官方修改链可表示 superseded | 跨来源冲突暴露率和 stale Evidence 行为 |
| H6 权限 | 无 | 公开数据没有真实权限差异，必须使用独立安全测试 |
| H7 可运营性 | 无 | 仍需要至少两名非开发人员完成标注和维护任务 |

公开数据消除了“没有任何数据所以无法验证”的阻塞，但没有消除产品价值、权限和运营成本证据缺口。

## 5. 下一步实验，不扩大产品范围

下一步不应立刻把 1,117 份合同全部导入，也不应先实现通用本体编辑器。更严谨的最小实验是：

1. 从 ContractNLI/CUAD 冻结一个小型 hidden test，覆盖当事方、生效、到期、续期、支持、反驳和未提及；
2. 从 USAspending 选择 10 个至少有一次修改的 Award family；
3. 从 TED 选择 10 条能回溯前一通知的修改链；
4. 用 GLEIF 构造带当前名称、历史名称和近似负例的组织 pair；
5. 在不改数据库的前提下，先用 CSV/JSON 构建 D/E 人工事实表；
6. 冻结至少 40 个问题，再运行 A/B/C 与 D/E/F；
7. 只有 D/E 在关系与时态问题上达到预注册增益，同时不损害普通文本问题，才讨论最小数据库实现。

公开代理实验的停止条件同样重要：如果 metadata filter C 已接近 D/E，或者结构化事实只改善法律条款分类而不能改善跨对象决策，就维持 `Don't build yet` 或 `Validate again`。

## 6. 可复现方法

```bash
python scripts/validate_public_ontology_data.py \
  --cache-dir /tmp/knowledge-public-validation \
  --output /tmp/ontology-public-validation.json
```

脚本检查：

- 固定下载 URL 和 SHA-256；
- 文档、标签和 Evidence 数量；
- 每个 Evidence/answer offset 是否能回到原文；
- Award transaction 数量、修改号、金额守恒和更新时间；
- TED 修改通知对前一通知的引用、稳定买方 ID、标题和 CPV；
- LEI、历史名称和登记机关 crosswalk；
- 所有检查的机器可读总数、通过数和失败项。

原始 ZIP 约 80 MB，只保存在指定 cache 目录，不提交仓库。公共 API 返回可能因官方更正而变化；固定对象 ID 和断言式检查使变化可以被检测，而不是静默覆盖既有结论。
